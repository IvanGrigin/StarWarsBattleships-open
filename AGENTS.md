# Правила работы AI-агентов

## Где работать

Рабочий репозиторий — открытый `IvanGrigin/StarWarsBattleships-open` на GitHub,
авторитетная ветка — `main`. Работа идёт **через форк**:

1. форкните репозиторий (`gh repo fork IvanGrigin/StarWarsBattleships-open --clone`),
   включите хук коммитов: `git config core.hooksPath .githooks`;
2. положите архив владельца `data.zip` в корень клона и распакуйте одной командой
   `unzip -o data.zip`, проверка — `python3 tools/check_assets.py` (см. `docs/ASSETS.md`);
   без него игра запускается на заглушках;
3. ведите работу в ветке своего форка и присылайте pull request в `main`
   открытого репозитория. В `main` напрямую не пушить, долгоживущие ветки в
   общем репозитории не заводить;
4. перед PR: `bash tools/run_ci_tests.sh`, `git fetch upstream`, rebase на
   `upstream/main`.

Картинки, 3D-модели, текстуры и аудио в git не добавлять — они под чужими
правами и живут только в архиве владельца. Папки ассетов внесены в `.gitignore`.

## Что читать перед правками

`docs/BASELINE-v0.4.1.md`, `docs/V0.5_DESIGN.md` (журнал решений и всего
сделанного в v0.5) и `docs/AI_COMMIT_POLICY.md`. Актуальная играбельная v4 —
`tools/play_v4/`; старое `demo/` — отдельный прототип v3.5. Баланс и корабли v4
определяются `data/rulesets/v4/`, `data/balance/` и `tools/sim_v4/`; разметка
моделей — `demo/assets/models/v4/index.json` (сами модели — в архиве).

## Коммиты

Каждый новый коммит AI-работника обязан соблюдать формат и пятизначную
последовательную нумерацию из `docs/AI_COMMIT_POLICY.md`, с временем, описанием
сделанного и причиной в теле. Не переписывать историю `main` и не заменять
размеченные модели/игровую логику визуальными фолбэками без решения владельца.

## Осторожность

Незакоммиченные файлы и результаты других агентов считать принадлежащими
владельцу. Перед слиянием или удалением проверять точные пути и сохранять
восстановимую копию. Игру проверять с выключенным звуком (он выключен по
умолчанию) и на своём порту (`--port`), не на порту, где играет владелец.
