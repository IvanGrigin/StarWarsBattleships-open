# ADR-014: Бой v3.1 — атакующий 2×d6, защищающийся d6 +1

Дата: 2026-09-13. Статус: принято (решение владельца проекта от 2026-09-13).

## Контекст

Решение владельца: «атакующий бросает два кубика, защищающийся только один, но у него +1 к защите, помимо разницы в гексах чисел» (секторные модификаторы остаются). Старый бой v3 (по d6 на сторону) давал атакующему среднее преимущество лишь +0.5 к среднему броску; симуляции RandomLegal показывали 88% ничьих по лимиту раундов — бои слишком редко решались. Новая механика смещает обмен в пользу атакующего на ~+1 в среднем (2d6 ≈ 7 против d6+1 ≈ 4.5) и усиливает значение сектора: заход в тыл двумя кубиками почти гарантирует выигрыш обмена.

## Решения

1. **Параметры боя — данные, не код.** В `data/rulesets/v3/game.json` добавлены поля `combat_attacker_dice: 2`, `combat_defender_dice: 1`, `combat_defender_flat_bonus: 1`; `ruleset_id` поднят до `v3_1`. Оба движка (GDScript-оракул и Rust `game_core`) читают эти поля; изменение будущих балансовых правок — одна правка данных.
2. **Формула.** Сила атакующего: `max(0, Σd6(атак.) + arc[сектор атакующего] − range_penalty)`; сила защитника: `max(0, Σd6(защ.) + flat_bonus + arc[сектор защитника])`. Далее конвейер без изменений: проигравший получает разность, ничья — 0, щит поглощает первым, min 0.
3. **Порядок потребления кубиков (pin, расширяет ADR-012 §2):**
   1. бросок атакующего d6₁;
   2. бросок атакующего d6₂;
   3. переброс стервятника (если есть): если хотя бы один из кубиков атакующего равен 1 — d2; успех → ровно один обязательный переброс одного кубика со значением 1 (при двух единицах — первого), новый результат окончателен; неудача → без изменений;
   4. бросок защищающегося d6;
   5. расчёт сил и применение урона — как в ADR-012 §2 п.5.
   Каждый физический бросок — отдельное событие `DieRolled` со своим `rng_index`; `dice`-журнал состояния пополняется в этом же порядке.
4. **События.** `StrengthCalculated` расширяется: `dice` — массив граней стороны (атакующий: два значения; защитник: одно), `flat_bonus` — плоский бонус защитника (у атакующего 0). Поле `die` сохраняется как СУММА граней стороны (совместимость читателей).
5. **X-wing «спорный шанс» и посмертные правила** — без изменений: условие «ничья» считается по новым итоговым силам.
6. **Миграция.** `ruleset_hash` меняется (game.json входит в хеш): golden-replay `tests/golden/replay_seed_42.jsonl` и диф-корпус `tests/golden/diff_corpus_100.jsonl` регенерируются санкционированной процедурой (удалить файл → прогон теста/экспортёра пересоздаёт); pin ruleset_hash в тестах Rust обновляется. Старые повторы v3 несовместимы с v3.1 и не воспроизводятся (ожидаемо).

## Последствия

- Средняя длина матча должна упасть; доля ничьих по лимиту — снизиться (проверить батчем 10 000 в M2-отчёте).
- Сектор стал важнее: контр-курс против 2d6 почти проигрышен → ценность манёвра и тыла выросла; ценность щита выросла (чаще поглощает).
- Балансовые веса карточек сместились: сильные передние дуги (Звезда Смерти 7, TIE Adv 3) усилились, «круглые» защитники (Разрушитель 2,2,1,1,1,2) — тоже; пересчёт в первом отчёте v3.1.
- Герои-реакции на броски (Оби-Ван, Люк) по-прежнему меняют ОДНУ грань; для атакующего с двумя кубиками — выбранную грань (уточнение в M2 при реализации героев).
