# ADR-009: Повторы — seed + команды + snapshots

Дата: 2026-09-13. Статус: принято.

## Контекст

Повтор матча нужен для отладки, споров о багах, аналитики и обучения. Требование: одинаковые seed и команды обязаны давать побайтово одинаковые события и hash состояния на каждом шаге.

## Решение

Повтор = исходный seed + журналы команд + периодические snapshot'ы + ruleset hash. Проверка повтора: переигрывание команд с нуля (`replay`) обязано воспроизвести сохранённые события и state hash; snapshot/restore не меняет продолжение матча.

## Последствия

- Детерминизм обязателен: один RNG-алгоритм (mulberry32), `rng_index` в каждом случайном событии, запрет float в состоянии (core-api §2, §3).
- Смена реализации RNG или формата canonical JSON = новая версия ruleset/protocol, старые повторы играются старым кодом.
- Golden-файлы генерируются только скриптами `tools/reference/*.py`, руками не правятся.
