# ADR-013: Предварительные решения этапа M0 (12 открытых вопросов + бюджет, устройства, IP)

Дата: 2026-09-13. Статус: **provisional** (каждое решение — предварительное).

## Контекст

Аудит (`GLM_AUDIT_RU.md` §6) перечислил 12 вопросов M0, которые не могут быть угаданы кодирующей нейросетью и должны быть закрыты владельцем дизайна. Владелец проекта на момент старта M2-подготовки не ответил; при этом без зафиксированных ответов блокируются контракты способностей (jango/boba/phasma), симуляции и Rust-ядро. Этот ADR фиксирует **предварительные** решения по каждому вопросу.

**Механизм отмены.** Каждое решение ниже имеет статус «provisional — может быть отменён владельцем одной правкой данных» (значение поля в `data/rulesets/v3/game.json`, карточке героя/корабля или сценарии) либо, для решений вне данных, — одной правкой этого ADR с последующим новым ADR. Никакое из решений не требует переписывания ядра: параметры вынесены в данные.

**Источник правил.** Официальный источник правил — Rust crate `game_core` (MASTER_PLAN_RU.md §5.1, ADR-003). GDScript-прототип (спринт 1, `src/**`, `tools/**`) сохраняется как reference-реализация и **дифференциальный оракул** для тестов Rust-ядра: его поведение считается нормативным до первых балансовых прогонов M2, а изменение семантики прототипа после заморозки требует обязательного дифференциального теста (см. `docs/contracts/rust-core-api.md`). Корабельные способности D1–D3 уже реализованы в прототипе по ADR-012; настоящие решения не меняют эти контракты, а придают им статус предварительных правил v3.

## Решения

### D1. X-wing «спорный шанс» — бонус только при ничьей

Способность `lucky_shot` (`xwing_t65`) работает **только когда X-wing — атакующий и бой закончился ничьей**: бросается d2; успех (2) → защитник получает **ровно 1 урон** (сначала щит; урон может уничтожить цель — тогда применяются её посмертные правила). Победа X-wing — обычный урон по разности сил; поражение — бонуса нет. Исходная фраза карточки («50% шанс нанести урон, минимум 1») не программируется буквально. [MASTER_PLAN §4.8; контракт реализации — ADR-012 §2/§6]

*Последствия:* ни одного нового поля состояния; кубик d2 потребляет match-RNG между бросками сторон (порядок pin — ADR-012 §2). Отмена владельцем = правка карточки `xwing_t65.json` + новый ADR.

### D2. Фантом — перенос текущих зарядов Призрака

При превращении `ghost → phantom` Фантом появляется в той же клетке и ориентации, с полным HP, нулевым щитом и зарядами, равными **текущим зарядам Призрака, обрезанным до `max_charges` карточки Фантома**: `charges = min(charges_ghost, max_charges("phantom"))`. Правило дата-управляемое: предел берётся из `ships/phantom.json`.

*Примечание к данным:* в текущем ruleset `phantom.json` задаёт `max_charges: 5`, `initial_charges: 3`; формулировка M0-черновика «срезанные до max_charges фантома (3)» соответствует стартовым зарядам (3), а не отдельному пределу. Если владелец намеревает жёсткий предел 3 — отмена одной правкой данных: `max_charges: 3` в `phantom.json`. Контракт превращения (событие `ShipTransformed`, отсутствие кубиков) — ADR-012 §4. [MASTER_PLAN §4.8]

### D3. Звезда Смерти — дальний выстрел

Способность `ranged_shot` (`death_star_1`): `DeclareAttack` разрешён на живого врага на **любом расстоянии** в пределах поля; штраф атакующему **−2 × (distance − 1)** к **итоговой** силе (`total = max(0, max(0, die + arc) − 2·(d−1))`; соседняя атака не штрафуется); **линия видимости кораблями НЕ блокируется** (v3 — открытый космос); **сектора обеих сторон считаются по направлению луча**. Определение направления луча для не-соседних клеток — целочисленная проекция без float (pin — ADR-012 §3); событие `StrengthCalculated` несёт `range_penalty`. [MASTER_PLAN §4.8; реализация — ADR-012 §3]

*Последствия:* герои/объекты, блокирующие видимость, могут появиться только будущим ruleset; отмена владельцем — правка `death_star_1.json` + новый ADR.

### D4. Фазма — область бонуса: корабли владельца, не команда

Пассивка `accuracy` (`phasma`): **+1 ко всем броскам при атаке кораблей ВЛАДЕЛЬЦА** (сида, выбравшего Фазму), **не всей команды**; защитные броски не усиливаются; действует до конца матча; в формуле core-api §4.4 входит слагаемым «permanent passives» (priority 0, до реакций). Соответствует данным `heroes/phasma.json` (`scope: attack_rolls_of_owner_ships`) и рекомендации MASTER_PLAN §4.9. [ADR-013 D4 определяет контракт; движок прототипа героев пока не исполняет — см. «Герои» ниже]

### D5. Мина Джанго — полный контракт

Способность `mine` (`jango_fett`), once per game:

- **Расход:** бесплатное действие (0 зарядов, атаку не расходует), раз в игру, только в свою активацию.
- **Установка:** в **текущую клетку** корабля владельца (клетка остаётся занятой самим кораблём; мина — маркер поверх клетки).
- **Триггер:** мина срабатывает, когда **ЛЮБОЙ корабль (включая союзный и вражеский) встаёт** — то есть входит после установки — **на клетку мины или соседнюю** (trigger radius 1). Корабли, стоящие в радиусе в момент установки (включая владельца на клетке мины), мину не подрывают: иначе установка в свою клетку была бы самоубийством.
- **Урон:** 1d4 (сначала щит, остаток корпус); может уничтожить.
- **Дружественный огонь:** включён (`friendly_fire: true`).
- **Блокировка:** мина **не блокирует клетку** и не мешает движению.
- **Срок жизни:** до срабатывания (после взрыва снимается с доски); конец матча снимает её тривиально.

*Последствия:* пины размещения «свободная клетка на расстоянии 1–2» в `heroes/jango_fett.json` **уступают** настоящему решению (установка в текущую клетку); выравнивание карточки — задача данных в M2 (карточка не исполняется движком до M2). Новые события `AbilityUsed`, `MinePlaced`, `MineTriggered` — по MASTER_PLAN §6.5.

### D6. Бомба Бобы — полный контракт

Способность `bomb` (`boba_fett`), once per game:

- **Расход:** бесплатное действие (0 зарядов, атаку не расходует), раз в игру, только в свою активацию.
- **Установка:** в **текущую клетку** корабля владельца; владелец выбирает направление `0..5` (core-api §1) **при установке; направление не меняется**.
- **Движение:** в **конце каждой активации владельца** бомба сдвигается на 1 клетку в выбранном направлении (событие `BombAdvanced`).
- **Срок:** максимум **3 сдвига**; после третьего без попадания — снимается без взрыва (despawn).
- **Взрыв:** при попадании (входе) в клетку с **любым** кораблём — 1d4 этому кораблю (сначала щит); дружественный огонь включён.
- **Край поля:** если следующая клетка сдвига вне поля — бомба снимается без взрыва (иначе детерминизм нарушается; явно зафиксировано этим ADR).

*Последствия:* пины `heroes/boba_fett.json` (запуск в соседнюю клетку, сдвиг в начале активации владельца) **уступают** настоящему решению; выравнивание карточки — задача данных в M2.

### D7. Движение после атаки — разрешено

Порядок действий внутри активации **свободный**: после атаки можно двигаться и поворачивать, пока есть заряды. Лимит **≤ 1 атака за активацию** сохраняется. [MASTER_PLAN §4.4; соответствует текущему поведению прототипа, core-api §4.2]

### D8. Стартовые зоны — текущий сценарий classic_2v2

Расстановка фиксируется сценарием `data/rulesets/v3/scenarios/classic_2v2.json` (без изменений данных): **A1 — юг** (facing 0, к северу), **B1 — север** (facing 3), **A2 — юго-запад** (facing 1), **B2 — северо-восток** (facing 4); команды занимают противостоящие пары углов: команда A — южная пара (A1 юг, A2 юго-запад), команда B — северная пара (B1 север, B2 северо-восток). Внутри сида корабли занимают клетки списка в порядке драфта (core-api §8).

### D9. Бюджет флота — 17

`draft_budget: 17` на сид — подтверждён как **балансный параметр**, а не окончательное правило; пересматривается симуляциями M2 (изменение = новая версия ruleset с новым hash, core-api §4.1).

### D10. Повторы группы 1 — не более 2 одинаковых типов у одного игрока

Ограничение драфта: один тип группы 1 — **не более 2 экземпляров у одного сида** (между игроками повторяться можно). Pin — `max_same_type_group1_per_seat: 2` в `game.json`; алгоритм отбора кандидатов — core-api §4.1.

### D11. Лимит раундов и сетевой таймер активации

- **Лимит 60 раундов**; `round > round_limit` → **ничья** (`reason: round_limit`). Tie-breaker по HP в v3 не используется.
- **Сетевой таймер активации: 60 секунд** с автоматическим `EndActivation` по истечении. Параметр ruleset — поле `activation_timeout_seconds` в `game.json` (значение `0` = таймер отключён: режим прототипа/offline). Серверная часть (измерение, авто-команда, reconnect-семантика) — **M5**; в GDScript-прототипе таймеров по-прежнему нет (core-api §4.2).

### D12. Целевые устройства

- **Desktop:** интегрированная графика уровня **Intel UHD 620 (2018+)**, **1080p @ 60 FPS**.
- **Mobile:** **iPhone SE 2 (Apple A13)** и **Android Snapdragon 665 / 4 GB RAM**, **720p @ 30 FPS**.

Значения — начальные цели профилей качества (MASTER_PLAN §9.2–9.3); после первого device-baseline-замера обновляются отдельным ADR (требование GLM_AUDIT_RU §5). Числа не входят в ruleset и на ядро не влияют.

### D13. IP-статус контента

Проект — **частный некоммерческий прототип** со Star Wars-материалами (карточки, названия, imagery). Minecraft-постройки создаются **собственные** (не копии чужих схем). **До любого публичного релиза** — ребрендинг на собственный сеттинг или получение лицензии; уточняет ADR-001 (лицензия/сеттинг) и `LICENSES.md`. Ограничение действует и на ассеты-производные (импорт Minecraft → GLB): публичный артефакт не должен содержать узнаваемых SW-названий и образов.

## Герои: объём действия решений

Герои **остаются вне experimental-ruleset прототипа до M2** (драфт героев отсутствует, движок способности героев не исполняет). Исключение — решения **D4–D6**, которые уже фиксируют **контракты способностей** (trigger/target/cost/effect/friendly_fire) и обязательны для M2-реализации C017–C019 и для Rust-ядра. Остальные уточнения героев (obi_wan, darth_vader, anakin, han_solo, luke) — по-прежнему открытые вопросы rules-v3 §9.6 до M2.

## Последствия

- `data/rulesets/v3/game.json` дополнен полями `activation_timeout_seconds: 60` и `ability_friendly_fire_default: true` (последнее — политика дружественного огня по умолчанию для способностей, не закрепивших её явно; D5/D6 закрепляют `true` явно). Схема `data/schemas/ruleset.schema.json` дополнена соответственно; `python3 tools/validate_data.py` остаётся зелёным.
- `docs/rules/rules-v3.md` получает точечные статусы «решено предварительно (ADR-013 D#)» вместо «deferred/открыт» для D1–D11.
- Контракт Rust-ядра: `docs/contracts/rust-core-api.md` (семантика 1:1 с `docs/contracts/core-api.md`).
- Отмена любого решения владельцем не требует изменения ядра, кроме D3 (встроен в бой) и D7 (порядок действий) — и там отмена = новый ADR + правила-правка + перегенерация golden-replay.
- До первых балансовых прогонов M2 поведение GDScript-прототипа — эталон; расхождения Rust-ядра с прототипом считаются багами Rust-ядра.
