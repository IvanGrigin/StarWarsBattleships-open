# Проверки перед попаданием в `main`

Общий набор тестов запускается командой `bash tools/run_ci_tests.sh`: проверка
данных v4 и v3, Python-тесты, синтаксис JavaScript, тесты ядра Rust и тесты
Godot. GitHub Actions запускает его для каждого push в `main` и каждого pull
request к `main`. Итоговый статус — `Project tests / tests`.

Локальный `.githooks/pre-push` запускает тот же набор до отправки изменений.
Чтобы включить хуки в другой рабочей копии, выполните
`git config core.hooksPath .githooks`. Хуки Git локальны и их можно обойти;
они не заменяют защиту ветки на сервере.

**Ограничение текущего GitHub-репозитория:** он приватный, а GitHub API
возвращает HTTP 403 для branch protection и rulesets с сообщением об
обновлении до GitHub Pro или переводе репозитория в публичный режим.
Поэтому неуспешный GitHub Actions run сейчас виден, но сам по себе не
запрещает прямой push или слияние. Статус нельзя считать обязательным,
пока это ограничение не снято.

После перехода на GitHub Pro (с сохранением приватности) либо после явно
одобренного владельцем перевода репозитория в публичный режим нужно создать
правило для `main`: требовать успешный `Project tests / tests` и
`AI commit policy / validate-new-commits`, запретить обход администратором,
удаление и force-push; при работе через pull requests дополнительно
потребовать PR перед слиянием. Публичность меняет доступ к коду и ассетам,
поэтому её нельзя включать автоматически.
