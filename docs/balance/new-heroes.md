# Как добавить нового героя и перенастроить баланс

Система баланса v4 — ML-оптимизатор `tools/sim_v4/optimize.py`. Он меняет только числа карточек:
у кораблей — сектора, корпус, щит и цену, у героев — цену в драфте. Способности героев остаются
как на карточках (решение владельцев от 2026-09-18).

## Шаги

1. **Карточка.** Добавить героя в генератор `tools/gen_v4_dataset.py` (фракция, эпоха, способность,
   синергия), пересобрать датасет и проверить валидатором:

   ```bash
   python3 tools/gen_v4_dataset.py
   python3 tools/validate_v4.py
   ```

2. **Правило в симуляторе.** Описать способность в `tools/sim_v4/rules.py`:
   - постоянный бонус — в `attack_mods` / `defense_mods`;
   - реакция на кубики — в `roll_attack`;
   - активная способность — вариант в `Match.hero_options` и эффект в `Match._hero_action`.
     Решение «когда применять» бот принимает сам по оценке позиции.

   Числа способности вынести в `tools/sim_v4/tune.py` (`DEFAULT`). Без этого шага симулятор играет
   героем без способности, и его цена получится заниженной.

3. **Стратегия героя.** Подобрать порог применения способности: первая стадия
   `python3 -m sim_v4.tuner` без `--strategy-from`, результат — в `tuning.json`.

4. **Баланс.** Запустить оптимизатор с новым героем. Новый герой попадает в каждую вторую партию,
   поэтому его сила оценивается точнее. Якоря задают, чьи числа двигать ради баланса:

   | Цель | Команда (из `tools/`) |
   |---|---|
   | Старые карточки уже напечатаны — подстраивается новый герой и корабли вокруг него | `python3 -m sim_v4.optimize --start sim_v4/patches/ml_best.json --new NEW_ID --anchor-new 0.2 --anchor-old 5` |
   | Новый герой печатается как задуман — подстраиваются старые карточки | `python3 -m sim_v4.optimize --start sim_v4/patches/ml_best.json --new NEW_ID --anchor-new 5 --anchor-old 0.3` |
   | Всё на равных | `python3 -m sim_v4.optimize --start sim_v4/patches/ml_best.json --new NEW_ID` |

   Якорь — множитель штрафа за изменение числа карточки. Большой якорь (5) почти запрещает
   менять карточку, маленький (0.2) разрешает менять её охотно.

5. **Результат.** Отчёт `reports/balance_v4_ml.md` показывает кандидатов с разным числом правок
   и насколько каждый выровнял баланс. Патч лучшего кандидата — `tools/sim_v4/patches/ml_best.json`.
   Решение о печати принимают владельцы; затем патч переносится в генератор датасета.

## Как устроен оптимизатор

- **Данные:** партии, в каждой из которых числа карточек случайно сдвинуты от текущего центра.
- **Модель:** логистическая регрессия. Шанс победы — функция силы карточек обеих сторон и
  сдвигов их чисел, плюс преимущество первого хода. Регуляризация подбирается по отложенной выборке.
- **Гиперпараметры:** штраф λ за изменённое число и набор рычагов («цены», «цены+сектора», «всё»).
  Для каждой пары оптимизатор выбирает целые сдвиги, приближающие силу каждой карточки к норме.
- **Проверка:** каждый кандидат играет честные партии без сдвигов. Лучший по отклонению процента
  побед от 50% становится центром следующего раунда. В следующем раунде модель дообучается на
  накопленных данных.
