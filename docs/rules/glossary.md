# Глоссарий терминов v3 (спринт 1)

Статус: справочный документ. Термины зафиксированы в `MASTER_PLAN_RU.md` §4.1 и `docs/rules/rules-v3.md` §1; норматив для кода — `docs/contracts/core-api.md`. Значения терминов не переопределяются этим документом: при расхождении приоритет у rules-v3.md и контракта. Изменение термина = правка rules-v3.md, а не глоссария.

Термины даны в объёме, который реально используется в спринте 1 (минимальный боевой контур). Способности героев и особые правила кораблей отключены до M2 (ADR-011) — связанные термины в глоссарий не включены.

---

## 1. Структура матча

- **Матч** — вся партия от создания до победы, ничьей или лимита раундов. (rules-v3 §1, §3; core-api §4.1)
- **Команда (team)** — два союзных места; команды `A = [A1, A2]` и `B = [B1, B2]`. (rules-v3 §1; core-api §4.1)
- **Место (seat, сид)** — позиция игрока в порядке ходов: `A1, B1, A2, B2`. Порядок хода — цикл `A1 → B1 → A2 → B2`. (rules-v3 §1, §5; core-api §4.1)
- **Раунд** — цикл, в котором каждый живой корабль получает ровно одну активацию. (rules-v3 §1, §6; core-api §4.2)
- **Активация** — последовательность действий одного выбранного корабля, завершаемая `EndActivation`. (rules-v3 §1, §6; core-api §4.2)
- **Действие** — движение вперёд, поворот, атака или завершение активации. (Способность как действие из MASTER_PLAN §4.1 в спринт 1 не входит.) (rules-v3 §1; core-api §4.2)
- **Фаза** — макросостояние матча: `draft → activation → ended`. В фазе `draft` идут драфт и расстановка, в `activation` — раунды, в `ended` матчевые команды отклоняются (`wrong_phase`). (rules-v3 §3; core-api §7)

## 2. Ресурсы и геометрия

- **Заряд** — ресурс конкретного корабля; старт 3, максимум 5. Движение вперёд — 1 заряд, поворот ±60° — 1 заряд, атака — 0 зарядов (не более 1 за активацию), в конце активации восстанавливается +1 заряд. (rules-v3 §1, §6; core-api §4.2)
- **Направление (facing)** — целое число `0..5`; `0` = север, рост по часовой стрелке; дельты — единственная таблица `DIR_DELTAS` (core-api §1). (rules-v3 §1; core-api §1)
- **Сектор** — сторона корабля, обращённая к цели: индексы `0..5` по часовой стрелке от переда с именами `F, FR, BR, B, BL, FL`; `sector_index = (dir_to_target - facing) mod 6`. Индексируется тем же порядком, что и `arc_modifiers` карточек. (rules-v3 §1, §7; core-api §1)
- **Гекс-расстояние** — `( |dq| + |dr| + |ds| ) / 2` в axial-координатах с cube-субкоординатой `s = -q - r`. (rules-v3 §1; core-api §1)
- **Соседний гекс** — клетка на гекс-расстоянии 1; бой в спринте 1 возможен только между соседями. (rules-v3 §1, §7; core-api §4.3)

## 3. Взаимодействие с ядром

- **Команда клиента** — запрос на действие (`{"type": ..., "command_id", "seat"}`), который ядро может отклонить; отклонённая команда не меняет состояние. (rules-v3 §1; core-api §5)
- **Событие** — подтверждённое ядром изменение состояния; создаётся только ядром. (rules-v3 §1; core-api §6)
- **Журнал (event journal)** — иммутабельная последовательность всех событий матча; UI, replay и сеть отображают журнал, а не пересчитывают правила. (core-api §6)
- **Ruleset** — версия правил и карточек с неизменяемым хешем (`v3`); в спринте 1 хеш считается по `game + board + ships`. (rules-v3 §1; core-api §8)

## 4. Драфт и расстановка

- **Драфт** — детерминированный выбор флотов: порядок `A1, B1, A2, B2`, 3 круга; выбор через `rng.next_below(n)` по отсортированному по `id` списку кандидатов; бюджет ≤ 17, ≤ 1 корабль группы 2, ≤ 2 одинаковых типа группы 1 на сид, корабли группы 2 уникальны в матче. (rules-v3 §4; core-api §4.1)
- **Драфтуемый корабль** — тип с `draftable: true` в `data/rulesets/v3/ships/`; «Фантом» в драфт не входит. (rules-v3 §1, §4; core-api §4.1)
- **Расстановка** — размещение флотов по сценарию `classic_2v2`: i-й корабль сида (в порядке драфта) ставится на i-ю клетку списка; facing один на сид — в сторону центра. (rules-v3 §5; core-api §8)

## 5. Состояние и воспроизводимость

- **Инстанс корабля (ship instance)** — конкретный корабль в матче; `ship_instance_id = "{seat}_{type_id}_{порядковый_номер_в_сиде_с_нуля}"`, например `A1_xwing_t65_0`. (core-api §7)
- **Canonical snapshot** — словарь состояния матча в каноническом JSON: ключи словарей отсортированы, без пробелов, целые — как целые, `bool` как `true/false`. (core-api §3, §7)
- **State hash** — FNV-1a 64 над UTF-8 байтами canonical-формы состояния; вывод — 16 hex-символов верхнего регистра; используется для сверок replay и round-trip. (core-api §3, §9)
- **rng_index** — порядковый номер вызова `next_die` с момента создания матча (счётчик с 0); записывается в событие `DieRolled`; порядок потребления кубиков — часть правил. (core-api §2, §6)
