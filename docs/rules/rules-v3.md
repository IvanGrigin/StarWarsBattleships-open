# Правила v3.0 — формализация (спринт 1: минимальный боевой контур)

Статус: нормативный документ правил v3.0. Норматив для кода — `docs/contracts/core-api.md` (его §4). Изменение правил = новый ADR + новая версия ruleset.

Область действия: **спринт 1 реализует минимальный боевой контур** — драфт, расстановку, раунды/активации, заряды и соседний бой. Особые способности кораблей и герои в движке спринта 1 были отключены (ADR-011) и включены данными в волне 3 (ADR-012, `"enabled": true`); герои движком по-прежнему не исполняются. Неясности формулировок перечислены в §9; их статусы обновлены по ADR-013 (см. ниже). Этот документ не выдаёт решения спорных вопросов за факты: всё, что не решено, помечено как открытый вопрос.

Источник всех чисел карточек — `MASTER_PLAN_RU.md` §4.7 (сверены с карточками PDF 2026-09-13, постранично, страницы 6–16). Машинные копии чисел: `data/rulesets/v3/` (проверяются `python3 tools/validate_data.py`).

Обновление (M0, ADR-013): двенадцать открытых вопросов M0 закрыты **предварительными** решениями `docs/decisions/ADR-013-m0-decisions.md` (каждое — provisional: отмена владельцем = одна правка данных). Ниже соответствующие пункты помечены «решено предварительно (ADR-013 D#)». Корабельные способности реализованы в GDScript-прототипе по контрактам ADR-012; прототип остаётся reference-реализацией и дифференциальным оракулом Rust-ядра (`docs/contracts/rust-core-api.md`).

## 1. Термины

- **Матч** — вся партия от создания до победы, ничьей или лимита раундов.
- **Команда (team)** — два союзных места; команды `A` и `B`.
- **Место (seat)** — позиция игрока в порядке ходов: `A1, B1, A2, B2`. Команды: `A = [A1, A2]`, `B = [B1, B2]`.
- **Раунд** — цикл, в котором каждый живой корабль получает ровно одну активацию.
- **Активация** — последовательность действий одного выбранного корабля, завершаемая `EndActivation`.
- **Действие** — движение вперёд, поворот, атака или завершение активации.
- **Заряд** — ресурс конкретного корабля; старт 3, максимум 5.
- **Направление (facing)** — целое число `0..5`; `0` = север, рост по часовой стрелке (таблица дельт — core-api §1).
- **Сектор** — одна из шести **сторон гекса** корабля, обращённая к цели: `F, FR, BR, B, BL, FL` (индексы `0..5`, по часовой стрелке от переда). Значение сектора изображается в середине соответствующей стороны, никогда на вершине. Для соседних клеток сектор задаёт их общая сторона: `sector_index = (dir_to_target - facing) mod 6`.
- **Гекс-расстояние** — `( |dq| + |dr| + |ds| ) / 2` в axial/cube-координатах, `s = -q - r`.
- **Событие** — подтверждённое ядром изменение состояния (иммутабельный журнал, core-api §6).
- **Команда клиента** — запрос на действие, который ядро может отклонить (core-api §5); отклонённая команда не меняет состояние.
- **Ruleset** — версия правил и карточек с неизменяемым хешем (`v3`).
- **Соседний гекс** — клетка на гекс-расстоянии 1.
- **Драфтуемый корабль** — тип с `draftable: true` в `data/rulesets/v3/ships/`.

## 2. Поле
Поле — правильный гексагон **радиуса 3: 37 клеток, диаметр 7** (v3.2, ADR-015; ранее — радиус 4 / 61 клетка).
Координаты axial `(q, r)`, клетка входит в поле при `max(|q|,|r|,|s|) ≤ 3`, `s = -q-r`.
Формат демо (v3.2) — дуэль «3 против 3»: сид A1 против B1, по 3 корабля, клинья напротив друг друга.
Полный формат 2×2 на 61 клетке возвращается сценарием на M5 (ADR-015).

## 3. Структура матча

1. Создание матча: `MatchCreated {ruleset_id, ruleset_hash, seed, round_limit}`; сиды назначаются как `A1, B1, A2, B2`.
2. Драфт флотов (§4).
3. Расстановка из сценария `classic_2v2` (§5).
4. `RoundStarted(1)`, активный сид `A1`.
5. Игроки по очереди активируют ещё не активированный в раунде живой корабль (§6).
6. После каждого применённого события-результата проверяется уничтожение и условие конца матча (§8).
7. При исчерпании всех активаций в раунде начинается следующий раунд; при `round > round_limit` — ничья.

Фазы состояния: `draft → activation → ended`.

## 4. Драфт

Ограничения флота (на каждый сид):

- **3 корабля** (fleet_size);
- бюджет стоимости **≤ 17** на сид (решено предварительно — ADR-013 D9);
- **≤ 1 корабль группы 2** на сид;
- корабли **группы 2 уникальны в матче** (один и тот же тип группы 2 не может быть взят двумя сидами);
- один тип **группы 1 — не более 2 экземпляров** у одного сида (решено предварительно — ADR-013 D10);
- **«Фантом» в драфте не участвует** (`draftable: false`); он появляется только из «Призрака» (способность отключена до M2, §9.1).

Детерминированный алгоритм драфта (норматив — core-api §4.1):

- Порядок выбора: `A1, B1, A2, B2`, по 3 круга.
- Кандидаты на каждом шаге — все типы из `data/rulesets/v3/ships/*.json` (кроме `draftable: false`), отсортированные по `id`, удовлетворяющие всем ограничениям выше и бюджету: `стоимость кандидата + текущая сумма ≤ 17 − минимальная сумма двух оставшихся разрешённых кораблей`.
- Выбор — `rng.next_below(n)` по этому отсортированному списку (один match-RNG; события `ShipDrafted`).
- Если допустимых кандидатов нет — ошибка конфигурации матча.
- Драфт героев в спринте 1 отсутствует: герои не выбираются и движком не используются (§9.6).

Бюджет 17 — балансный параметр, а не окончательное правило (решено предварительно — ADR-013 D9; пересматривается симуляциями M2); изменение проходит через новую версию ruleset.

## 5. Расстановка

Расстановка берётся из `data/rulesets/v3/scenarios/classic_2v2.json` (числа — core-api §8):

| Сид | Клетки (q, r) | Facing |
|---|---|---|
| A1 | `[0,4]`, `[0,3]`, `[1,3]` | 0 |
| B1 | `[0,-4]`, `[0,-3]`, `[-1,-3]` | 3 |
| A2 | `[-4,4]`, `[-4,3]`, `[-3,3]` | 1 |
| B2 | `[4,-4]`, `[4,-3]`, `[3,-3]` | 4 |

- i-й корабль сида (в порядке драфта) ставится на i-ю клетку списка.
- Facing один на сид и направлен к центру поля.
- Порядок хода: `A1 → B1 → A2 → B2`.
- Стартовые зоны решены предварительно (ADR-013 D8): A1 — юг, B1 — север, A2 — юго-запад, B2 — северо-восток; команды занимают противостоящие пары углов (команда A — южная пара, команда B — северная).

## 6. Раунд и активация

- **Раунд**: каждый живой корабль активируется **ровно один раз**. Сиды без неактивированных живых кораблей пропускаются. Когда таких кораблей нет ни у кого — `RoundStarted(round + 1)`, флаги `activated` сбрасываются.
- Начало матча: `RoundStarted(1)`, активный сид `A1`.
- **Заряды**: старт **3**, максимум **5**.
  - Движение вперёд на 1 гекс по текущему направлению — **1 заряд**.
  - Поворот на ±60° — **1 заряд**.
  - Атака — **0 зарядов**, но **не более 1 за активацию**.
  - В конце активации (только по `EndActivation`) корабль восстанавливает **+1 заряд** до максимума 5. Щиты не восстанавливаются никогда (§7).
- Порядок действий внутри активации свободный (можно двигаться после атаки), если хватает зарядов и атака не израсходована — решено предварительно (ADR-013 D7).
- Активацию можно завершить в любой момент командой `EndActivation`; в спринте 1 принудительных тайм-аутов нет. (Тайм-аут с серверным `EndActivation` — решён предварительно, ADR-013 D11: сетевой таймер 60 секунд, затем авто-`EndActivation`; параметр ruleset `activation_timeout_seconds`, серверная часть — M5; см. §9.7.)
- Поворот меняет только facing, позиция не меняется; движение меняет только клетку, facing не меняется. Движение возможно только в свободную соседнюю клетку в направлении facing.

## 7. Бой

Бой возможен **только между кораблями на соседних гексах** (единственное исключение — дальний выстрел Звезды Смерти, §9.2: решено предварительно — ADR-013 D3; реализация в прототипе — ADR-012 §3).

Последовательность (норматив — core-api §4.3):

1. `DeclareAttack(target)`: цель — живой корабль вражеской команды на соседнем гексе; у атакующего не израсходована атака этой активации.
2. Сектор атакующего: `sector_index(facing_att, direction_from(att_cell, tgt_cell))`. Сектор защищающегося: `sector_index(facing_def, direction_from(def_cell, att_cell))`.
3. Кубики из единственного match-RNG (v3.1, ADR-014): **атакующий бросает 2×d6** (два события `DieRolled`, `role: attacker`), затем — проверки способностей атакующего (стервятник, ADR-014 §3), затем **защищающийся бросает 1×d6** (`role: defender`). Каждому броску — свой `rng_index`.
4. Сила сторон (v3.1): атакующий `max(0, d6₁ + d6₂ + arc_modifiers[сектор атакующего] − range_penalty)`; защищающийся `max(0, d6 + flat_bonus + arc_modifiers[сектор защитника])`, где `flat_bonus = combat_defender_flat_bonus` (v3.1: +1). Параметры бросков читаются из `game.json` (`combat_attacker_dice`, `combat_defender_dice`, `combat_defender_flat_bonus`). Отрицательные модификаторы могут обнулить силу, но не сделать её отрицательной.
5. **Проигравший** (меньшая сила) получает урон, равный **разности сил**. При **равенстве сил урона нет** (ничья = 0).
6. Урон сначала снимает **щит**, остаток — здоровье. Щит **не восстанавливается** до конца матча.
7. `HP ≤ 0` → `ShipDestroyed`; корабль убирается с доски. Посмертные правила (превращение §9.1, воскрешение §9.4) применяются по контрактам ADR-012 (§2, §4–§5; статус предварительный — ADR-013); в базовом бою без способностей уничтожение окончательно.
8. После применения каждой команды проверяется конец матча (§8).

Зарезервированная на весь проект формула модификаторов (в спринте 1 существует только `die + arc`):

```text
base die + sector arc + permanent passives + temporary statuses + range + reactions = final (min 0)
```

### 7.1. Размеченные примеры боя

Числа кубиков иллюстративные; сектора считаются по правилам §7. Направления: 0=N, 1=NE, 2=SE, 3=S, 4=SW, 5=NW.

**Пример 1. X-wing атакует TIE-истребитель в лоб.**
X-wing (arc `[2,1,0,1,0,1]`, facing 0), TIE (arc `[2,1,0,0,0,1]`, facing 0) стоит прямо по курсу (dir 0).
- Сектор атакующего: `(0−0) mod 6 = 0` → F → `+2`. Сектор TIE: направление от TIE к X-wing = 3 (S), `(3−0) mod 6 = 3` → B → `+0`.
- Броски: атакующий **4**, защищающийся **5**. Силы: `max(0, 4+2)=6` против `max(0, 5+0)=5`.
- Разница 1 → TIE (щита нет) получает 1 урон корпуса: `hp 4 → 3`.
- Вариант-ничья: при бросках 3 и 5 силы `3+2=5` и `5+0=5` — равенство, урона нет ни у кого.

**Пример 2. TIE Advanced X1 атакует Сокол тысячелетия сзади.**
TIE Adv (arc `[3,1,1,0,1,1]`, facing 0), Сокол (arc `[2,1,2,0,2,1]`, facing 0) стоит впереди по курсу (dir 0 от TIE).
- Сектор TIE Adv: F → `+3`. Сектор Сокола: направление от Сокола к TIE = 3 → B (индекс 3) → `+0`.
- Броски: **6** и **3**. Силы: `6+3=9` против `3+0=3`. Разница 6.
- Щит Сокола 1 поглощает 1 урон (щит `1 → 0`), остальные 5 снимают корпус: `hp 8 → 3`.

**Пример 3. X-wing бьёт Звезду Смерти сзади (отрицательный сектор).**
Звезда Смерти (arc `[7,0,0,−1,0,0]`, facing 0), X-wing стоит сзади (dir 3 от Звезды), сам X-wing имеет facing 3 и видит Звезду по курсу.
- Сектор Звезды: `(3−0) mod 6 = 3` → B → `−1`. Бросок защищающегося **1**: сила `max(0, 1−1)=0`.
- Сектор X-wing: F → `+2`. Бросок атакующего **1**: сила `1+2=3`.
- Разница 3: щит Звезды 2 поглощает 2 (щит `2 → 0`), 1 урон корпуса: `hp 11 → 10`.

**Пример 4. Дроид-стервятник атакует Звёздный разрушитель в лоб — выигрывает защищающийся.**
Стервятник (arc `[1,1,1,0,1,1]`, facing 0), разрушитель (arc `[2,2,1,1,1,2]`, facing 0) прямо по курсу.
- Сектор стервятника: F → `+1`. Сектор разрушителя: направление к стервятнику = 3 → B (индекс 3) → `+1`.
- Броски: **2** и **4**. Силы: `2+1=3` против `4+1=5`.
- Проигравший — атакующий: стервятник (щита нет) получает 2 урона корпуса: `hp 4 → 2`.

## 8. Уничтожение и конец матча

- Корабль с `hp ≤ 0` уничтожается (`ShipDestroyed`) и убирается с доски; посмертные свойства (§9.1, §9.4) применяются только по контрактам ADR-012/ADR-013, в базовом бою уничтожение окончательно.
- **Победа**: у команды нет живых кораблей → поражение этой команды.
- Если после одной атомарной цепочки событий пусты **обе** команды — **ничья** (`reason: both_eliminated`).
- **Лимит раундов 60**: `round > round_limit` — ничья (`reason: round_limit`) — решено предварительно (ADR-013 D11). Tie-breaker по оставшемуся HP в v3 не используется (может быть включён только будущим ruleset).
- Сдача/отключение игрока в спринте 1 не моделируется (§9.7).

## 9. Открытые вопросы карточек — статус: deferred to M2

Все перечисленные ниже вопросы **не решены окончательно этим документом**. Статусы обновлены (ADR-013): пункты §9.1–§9.3 и контракты Фазмы/мины/бомбы (§9.6) получили статус «решено предварительно (ADR-013 D#)» — предварительные решения, отмена владельцем = одна правка данных; пункты §9.4–§9.5 (воскрешение СИД, переброс стервятника) реализованы в прототипе по контрактам ADR-012 (§2, §5) и в список D не входят — их подтверждение владельцем остаётся за M2. В движке спринта 1 способности кораблей реализованы по ADR-012 (`"enabled": true`), герои не выбираются в драфте. Данные карточек хранятся **полностью** (`abilities`, `heroes/*.json`). Формулировки-источники — `MASTER_PLAN_RU.md` §4.8/§4.9 и «Правила Игры.txt».

9.1. **Призрак → Фантом** (`ghost`, ability `transform_to_phantom`). Карточка: «при взрыве превращается в Фантом». **Решено предварительно (ADR-013 D2):** точный контракт превращения — Фантом появляется в той же клетке и ориентации, с полным HP, нулевым щитом; заряды — текущие заряды Призрака, обрезанные до `max_charges` фантома: `charges = min(charges_ghost, max_charges("phantom"))` (правило дата-управляемое; примечание о `(3)` в черновике M0 — ADR-013 D2). Реализация в прототипе — ADR-012 §4.

9.2. **Дальний выстрел Звезды Смерти** (`death_star_1`, ability `ranged_shot`). Карточка: «может атаковать корабль на любое расстояние (каждая клетка −2 к силе)». **Решено предварительно (ADR-013 D3):** штраф `−2 × (distance − 1)` к **итоговой** силе атакующего (соседняя атака не штрафуется); **линия видимости кораблями НЕ блокируется**; **сектора обеих сторон — по направлению луча**. Целочисленное определение направления луча для не-соседних клеток — ADR-012 §3; реализация в прототипе — там же.

9.3. **X-wing, «спорный шанс минимального урона»** (`xwing_t65`, ability `lucky_shot`). Карточка: «при атаке 50% шанс нанести урон (минимум 1)». Фразу нельзя программировать буквально. **Решено предварительно (ADR-013 D1):** бонус работает только при ничьей, когда X-wing — атакующий: d2, успех (2) → ровно 1 урон защитнику (сначала щит); победа — обычный урон по разности сил; поражение — бонуса нет. Реализация в прототипе — ADR-012 §6.

9.4. **Воскрешение истребителя СИД** (`tie_fighter`, ability `resurrection`). Карточка: «с шансом ½ корабль воскреснет с жизнями d4». Не решено: одна попытка за экземпляр (рекомендация мастера-плана), состояние щита/зарядов после воскрешения, откладывание события уничтожения до результата попытки. Реализация в прототипе (одна попытка, `revive_used`, отложенный `ShipDestroyed`, hp = d4, щит 0) — ADR-012 §5; финальное подтверждение владельцем — M2.

9.5. **Переброс дроида-стервятника** (`vulture_droid`, ability `reroll_one`). Карточка: «с шансом ½ может перебросить кубик, если выпало 1 при атаке». С v3.1 (ADR-014 §3): после двух бросков атакующего, если ХОТЯ БЫ ОДИН кубик равен 1 — d2; успех → ровно один обязательный переброс ОДНОГО кубика со значением 1 (если оба — первого), второй результат окончателен даже если снова 1. Расход `rng_index` — по порядку событий.

9.6. **Герои (все 8)** — не участвуют в спринте 1 (драфт героев отсутствует). Данные в `data/rulesets/v3/heroes/*.json`, тексты дословно из исходных правил; `timing` — заглушка `undefined_v3` (кроме Фазмы). Не решённые уточнения по мастеру-плану §4.9:

Статус героев (ADR-013): герои остаются **вне experimental-ruleset прототипа до M2** (драфт героев отсутствует, движок способности героев не исполняет). Исключение — зафиксированные решения **D4–D6 (ADR-013)**, которые уже определяют **контракты способностей** для M2 и Rust-ядра:

- **D4 — Фазма:** +1 ко всем броскам при атаке кораблей **владельца** (не команды); защитные броски не усиливаются; совпадает с данными `heroes/phasma.json` (`scope: attack_rolls_of_owner_ships`).
- **D5 — мина Джанго:** бесплатное действие раз в игру в свою активацию; установка в **текущую клетку**; срабатывает при входе любого корабля (включая союзного) на клетку мины или соседнюю после установки; 1d4; дружественный огонь включён; клетку не блокирует; живёт до срабатывания. Пин «свободная клетка на расстоянии 1–2» в `jango_fett.json` уступает решению.
- **D6 — бомба Бобы:** бесплатное действие раз в игру в свою активацию; установка в **текущую клетку** с выбором направления, которое затем не меняется; сдвиг на 1 клетку в **конце каждой активации владельца**; максимум 3 сдвига (потом despawn; вне поля — тоже despawn без взрыва); взрыв при входе в клетку с любым кораблём; 1d4; дружественный огонь включён. Пины `boba_fett.json` (запуск в соседнюю клетку, сдвиг в начале активации) уступают решению.

Выравнивание карточек `heroes/jango_fett.json` и `heroes/boba_fett.json` с ADR-013 D5/D6 — задача данных в M2 (до M2 карточки движком не исполняются).

9.7. **Прочие отложенные правила** (вне минимального контура): тайм-аут активации с серверным `EndActivation` — **решён предварительно (ADR-013 D11)**: сетевой таймер 60 секунд, затем авто-`EndActivation`; параметр ruleset `activation_timeout_seconds` (`game.json`), серверная часть — M5. Остальное остаётся отложенным: сдача игрока/команды и bot takeover; героев-драфт «змейкой»; tie-breaker по HP; произвольные сценарии расстановки.
