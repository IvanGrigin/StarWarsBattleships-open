# Единая базовая версия v0.4.1

Дата сведения: 23 сентября 2026 года. Авторитетная ветка: `main`. Это точка,
от которой следует начинать работу над v0.5. Предыдущие коммиты не переписаны.

## Как получена версия

Локальная `main` на `4d676a8` была прямым предком ветки Claude
`claude/game-balance-card-mechanics-3ff9ba` на `6f8a350`. Она быстро
переведена на этот коммит без конфликтного Git-слияния. `origin/main` уже
указывала на `6f8a350`; других веток GLM/Codex локально или на `origin`
на момент сведения не было. Их работы, если они есть, представлены общей
историей и незакоммиченными файлами, а не отдельными ссылками Git.

Из старой рабочей копии сохранены правило «шесть значений на шести сторонах»,
универсальный компонент `<swb-ship-hex>`, правки документации и выбор моделей
в `tools/model_preview/tournament.json`. Два конфликтовавших файла рулбука
пересобраны из объединённых карточек актуальным `tools/gen_rulebook.py`.

Отклонённый редизайн старого демо и промежуточные симуляции помещены в
`archive/pre-v0.4.1/` и не подключены к игре. Архив содержит патч исходных
незакоммиченных правок; его нельзя применять целиком как обновление v4.

## Источники истины

| Область | Авторитетный путь | Примечание |
| --- | --- | --- |
| Играбельная v4 | `tools/play_v4/` | Python-сервер и интерфейс Three.js; клик выбирает, действия только кнопками. |
| Симуляция и правила v4 | `tools/sim_v4/` | Тот же боевой механизм, что использует сервер v4. |
| Карточки v4 | `data/rulesets/v4/`, `data/balance/v4_patch.json` | 50 кораблей, 32 героя, три эпохи; генератор `tools/gen_v4_dataset.py`. |
| 3D-модели v4 | `demo/assets/models/v4/` | 47 GLB с индексом источников и запечённой ориентацией. |
| Секторный жетон v4 | `tools/play_v4/components/ship-hex-token.js` | Снимок сверху строится из той же модели, что стоит на поле. |
| Рулбук v4 | `tools/gen_rulebook.py` → `docs/rulebook/` | HTML — генерируемый результат, не редактировать вручную. |
| Предыдущая игра v3.5 | `demo/`, `rust/game_core/` | Самостоятельный старый прототип, не основа дизайна v4. |

У v4 пока нет отдельных GLB для `mg100_bomber`, `nantex_fighter` и
`punishing_one`: для них интерфейс использует предусмотренный фолбэк. Это
не повод заменять или переориентировать уже размеченные 47 моделей.
В полной картотеке есть изображения 46 из 50 кораблей. Частный фанатский
прототип не следует публиковать без проверки прав на IP и внешние ассеты;
см. `LICENSES.md` и `docs/STEAM_COMMERCIAL_MATRIX.md`.

## Что считать неизменным при визуальной работе

- Не менять карточки, баланс, расчёт боя, порядок активации и API команд,
  если задача касается только дизайна.
- Шесть чисел соответствуют **сторонам**, не вершинам гекса. У соседних
  кораблей используется общая сторона двух клеток.
- Для моделей контракт ориентации: нос `−Z`, верх `+Y`, игровой курс
  `rotation.y = 30° − 60° × facing`. Сведения об источнике и ориентации
  хранятся в индексе v4; не заменять их процедурными силуэтами ради стиля.
- Действующий экран для дальнейшего редизайна — `tools/play_v4/`, не
  `demo/` или `browser-demo/dist/`.

## Проверки перед следующей версией

```bash
python3 tools/validate_v4.py
python3 tools/validate_data.py
python3 tools/gen_rulebook.py
python3 -m unittest discover -s tests -p test_commit_policy.py
cargo test --release --manifest-path rust/game_core/Cargo.toml
godot --headless --path . --script res://tools/run_tests.gd
node --check tools/play_v4/game.js
node --check tools/play_v4/components/ship-hex-token.js
git diff --check
```

Для ручной проверки игры: `python3 tools/play_v4/server.py --cards`, затем
открыть `http://localhost:8766/`. `--cards` использует числа самих карточек;
отдельный оптимизационный патч поверх них не накладывается.

## Правила дальнейших коммитов

Формат и обязательные поля всех AI-коммитов определяет
`docs/AI_COMMIT_POLICY.md`; локальный хук `.githooks/commit-msg` и CI проверяют
новые сообщения. Нумерация v0.4.1 начинается с `00001`. Следующую версию и
номер сброса счётчика утверждает владелец проекта.
