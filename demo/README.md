# Star Wars Battleships — веб-демо (demo/)

Статичный браузерный клиент (HTML/CSS/JS, без фреймворков и внешних ассетов) поверх
WASM-ядра. Работает в двух режимах:

- **Боевой**: рядом подключён клей `window.swb` (появится в `demo/pkg/` после сборки WASM).
- **ДЕМО-МОК**: если `window.swb` не найден (штатная ситуация до сборки ядра),
  `main.js` сам подгружает `demo/mock_core.js` и показывает жёлтую плашку «ДЕМО-МОК».
  Параметр `?mock=1` включает мок принудительно, даже если ядро есть.

## Запуск (одна команда)

```bash
python3 -m http.server 8901 --directory demo
```

Открыть: <http://localhost:8901/?mock=1> (или просто <http://localhost:8901/> —
без ядра мок включится автоматически). Никаких сборок и внешних запросов.

Полный каталог и проверка ориентации в шести курсах:
<http://localhost:8901/orientation_test.html>. Нос любой исходной модели до
размещения на поле должен смотреть по `−Z`, верх — по `+Y`; поле само добавляет
курс `0…5` поворотом вокруг Y с шагом 60°. Страница показывает 11 игровых
источников и все 26 Minecraft-мешей, включая библиотечные варианты.

Интерактивный стенд воспроизводимого жетона корабля:
<http://localhost:8901/ship_hex_token_gallery.html>. Компонент принимает любую
прозрачную модель, курс и шесть чисел; корабль и бейджи всегда остаются внутри
pointy-top гекса. API и примеры описаны в `components/ship-hex-token.md`.

## Управление

- Игрок — **команда A** (сид A1, три корабля), бот — **команда B** (сид B1,
  три корабля), ходят по циклу A1→B1.
- **Выбор корабля**: когда активного корабля нет, свои неактивированные корабли подсвечены
  зелёным; клик по клетке корабля (или кнопке «Выбрать: …») — начало активации.
- **Движение**: голубая подсветка доступных соседних клеток; клик по ней или кнопка.
- **Поворот**: кнопки «Поворот влево ↺ / вправо ↻» (−1 заряд, метка нового курса в кнопке).
- **Атака**: красные кнопки целей с предпросмотром «ты F+2 · он B+1» (секторы и бонусы арок,
  для Звезды Смерти — ещё штраф дистанции); клик по подсвеченной красным цели тоже атакует.
- **Завершить активацию**: кнопка завершения хода выбранного корабля.
- Метка курса у корабля — стрелка ↑ ↗ ↘ ↓ ↙ ↖ (facing 0..5, по часовой от севера).

## Что где на экране

- **Слева (или сверху на узком экране)** — 3D-поле 37 гексов (radius 3,
  pointy-top axial), процедурные силуэты кораблей носом по курсу, командные кольца
  (синие — A, красные — B), полоски HP/щита, подсветки (зелёная пульсация — можно
  активировать, голубая — клетка хода, красная — цели атаки, жёлтый пунктир — активный корабль).
- **Справа (снизу)** — панель: раунд и чей ход; карточка активного корабля (HP, щит,
  заряды ●●○○○, «атака использована», способности); кнопки действий (строится из
  `legal_actions`); журнал последних 8 событий; легенда; кнопка «Новая игра».
- **Оверлей** в конце матча: «Победа команды A/B» или «Ничья» + причина + «Сыграть ещё»
  (новый случайный seed).

## Контракт ядра (window.swb)

Все функции синхронные, обмениваются JSON-строками:

```js
swb.create_match(seed /*int*/, round_limit /*int*/) -> String  // JSON состояния
swb.legal_actions(state_json /*String*/) -> String             // JSON-массив команд
swb.apply_command(state_json, cmd_json) -> String
//   {"ok":true,"events":[...],"state":{...}} | {"ok":false,"error":"код"}
swb.state_hash(state_json) -> String
```

Команды: `BeginActivation{ship_instance_id}`, `Move{dir}`, `RotateLeft`, `RotateRight`,
`DeclareAttack{target_ship_instance_id}`, `EndActivation`. Имена полей состояния и событий —
по `rust/game_core/src/engine.rs` (serde-структуры) и `docs/contracts/core-api.md` §5–§7.

Чтобы подключить реальное ядро: добавить `demo/pkg/<клей>.js`, определяющий `window.swb`,
в `index.html` **до** `main.js` — код фронтенда менять не нужно.

## Мок (mock_core.js)

Упрощённая, но играбельная заглушка: 3 корабля против 3 на стартовых клетках
`classic_2v2`, движение/повороты/соседний бой с фейковыми кубиками (LCG от seed).
Защитный лимит равен 180 успешным командам и может быть переопределён через
`window.SWB_MOCK_ACTION_LIMIT`. Спецспособности (ADR-012) в моке не симулируются —
их логирование проверяется на реальном ядре.

## Бот (bot.js)

Жадная эвристика, всегда выбирает команду из `legal_actions`:

1. `BeginActivation` — свой корабль с минимальной дистанцией до ближайшего врага;
2. если легальна атака — цель с максимумом `(arc_attacker − arc_defender)`;
3. иначе `MoveForward`, если клетка впереди сокращает дистанцию до ближайшего врага;
4. иначе поворот (±60°), при котором ближайший враг попадает в более сильный сектор;
5. иначе `EndActivation`; на нештатных ветках — случайный легальный элемент.
